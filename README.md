# Портал для зоологов — каталог черепах

Учебное веб-приложение на Laravel 12, Blade, Bootstrap 5, SCSS и SQLite.

## Структура

- `app/Http/Controllers/` — обработка HTTP-запросов.
- `app/Http/Requests/` — серверная валидация.
- `app/Models/` — модели Eloquent.
- `app/Services/` — обработка изображений.
- `resources/views/layouts/` — общий каркас и части интерфейса.
- `resources/views/turtles/` — страницы каталога и формы.
- `resources/js/` и `resources/scss/` — исходники фронтенда.
- `database/migrations/`, `database/seeders/` — схема и начальные данные.
- `routes/web.php` — веб-маршруты.
- `public/build/` — автоматически собранные Vite ресурсы (не коммитятся).
- `tests/` — автоматические тесты.

Конфигурации Laravel, Composer, npm и Vite остаются на стандартных местах.

## Запуск

Требования: PHP 8.2+, Composer, Node.js 20.19+ (ветка 20) или 22.12+, npm, расширения PHP PDO SQLite и GD (для изображений).

При первом запуске установите зависимости, создайте `.env` из `.env.example` и пустую SQLite-базу `database/database.sqlite`, если их ещё нет. Не заменяйте существующую базу или `.env`.

```bash
composer install
npm install
php artisan key:generate
php artisan migrate
php artisan storage:link
npm run build
php artisan serve
```

Команда `key:generate` нужна только для новой установки без APP_KEY; `storage:link` — если ссылка ещё отсутствует. Для первоначальных демонстрационных данных можно выполнить `php artisan db:seed`.

При переходе на lab-4 из lab-3 выполните `npm install` и `npm run build`. Vite заменяет Laravel Mix, Webpack и jQuery; сгенерированные файлы сборки не являются исходниками.

Для разработки с автоматическим обновлением используйте `npm run dev` в отдельном терминале параллельно с `php artisan serve`.

## Тестирование

```bash
php artisan test
```

Тесты используют отдельную тестовую базу и не требуют собранного фронтенда. Внешний вид и работу JavaScript проверяйте после `npm run build`.

## Авторизация (лабораторная №4, пункт 2)

Laravel Breeze v2.4.2 добавлен как dev-зависимость; контроллеры регистрации и сессии и LoginRequest основаны на его официальных Blade-заготовках. Формы адаптированы под существующий Bootstrap layout. Лицензия: `docs/licenses/laravel-breeze.txt`.

После обновления ветки выполните `composer install` и `php artisan migrate`. Не запускайте `php artisan breeze:install` поверх адаптированных шаблонов: он может перезаписать frontend-конфигурацию и маршруты.

- `/login` — вход; `/register` — регистрация; `POST /logout` — выход.
- Восстановление пароля, верификация email и профиль не включены в этот этап.
- В пункте 3 добавлены связи моделей и привязка объектов к пользователям.

## Каталоги пользователей (пункт 3)

- Общий каталог остаётся публичным, а список пользователей (`/users`) и их каталоги (`/users/{username}/turtles`) доступны после входа.
- Новые черепахи автоматически получают ID текущего пользователя. Изменять и мягко удалять записи может владелец или администратор.
- Старые записи без владельца сохраняются в общем каталоге. После регистрации пользователей назначьте им записи вручную через Tinker, используя реальные ID своей базы:

```php
App\Models\User::select('id', 'name')->get();
App\Models\Turtle::withTrashed()->get(['id', 'name', 'user_id']);
App\Models\Turtle::withTrashed()->whereNull('user_id')->whereIn('id', [1, 2])->update(['user_id' => 1]);
App\Models\Turtle::withTrashed()->whereNull('user_id')->whereIn('id', [3, 4, 5])->update(['user_id' => 2]);
```

Перед назначением проверьте ID пользователей и объектов. Существующие владельцы не перезаписываются.

При регистрации email должен содержать полный домен с точкой, например `name@gmail.com`. Проверка формата не подтверждает существование почтового ящика и не изменяет старые аккаунты.

## Роль администратора (пункт 4)

Миграция добавляет в таблицу `users` булев флаг `is_admin` со значением по умолчанию `false`. После обновления ветки выполните `php artisan migrate`.

Назначьте администратора вручную через `php artisan tinker`. Сначала проверьте список пользователей:

```php
App\Models\User::all(['id', 'name', 'email', 'is_admin']);
```

Затем выберите ID нужной учётной записи (здесь для примера 1):

```php
$user = App\Models\User::findOrFail(1);
$user->is_admin = true;
$user->save();
$user->refresh()->isAdmin();
```

Флаг не входит в `$fillable` и не принимается при регистрации. Для снятия роли присвойте `false` и сохраните модель. Административные разрешения и управление удалёнными объектами описаны в пункте 5.

## Права доступа и Soft Deletes (пункт 5)

- Gates определены в `AppServiceProvider`; контроллеры и Form Request проверяют разрешения, Blade использует `@can`, а события `creating`, `updating`, `deleting`, `restoring` модели Turtle защищают операции над её экземплярами.
- Гость видит общий каталог и активные записи. Авторизованный пользователь видит каталоги всех пользователей, создаёт свои записи и редактирует/мягко удаляет только свои.
- Администратор может редактировать и мягко удалять любые активные записи. В каталоге выбранного пользователя он видит также удалённые записи; общая корзина находится по адресу `/admin/turtles/trash`.
- Восстановление: `PATCH /turtles/{id}/restore`. Окончательное удаление: `DELETE /turtles/{id}/force`. Оба действия доступны только администратору и только для мягко удалённых записей. Восстановление блокируется при совпадении латинского названия с активной записью.
- При окончательном удалении удаляется строка базы, изображения сохраняются (могут использоваться другими объектами).
- Доверенные CLI-операции без веб-пользователя (Tinker, сидеры) не ограничены веб-ролями. Массовые операции через Query Builder не вызывают событий модели, поэтому не используются в пользовательских маршрутах.
- Для проверки выполните `php artisan test` и проверьте права на сайте под двумя обычными пользователями и администратором.

## Username в ссылках на каталоги (расширенный уровень)

После `php artisan migrate` существующие пользователи получают уникальные username на основе имени: например, `amogus`, `amogus_2`. Их ID, email, пароли, роли и связи с черепахами не меняются. Миграция добавляет колонку и уникальный индекс без пересоздания таблицы users; колонка допускает NULL на уровне БД для безопасного обновления существующей SQLite-схемы, а при регистрации username обязателен.

Новые пользователи указывают уникальный username (3–32 символа, первая буква латинская, далее строчные латинские буквы, цифры и подчёркивания). Авторизация остаётся по email и паролю.

Маршрут `/users/{username}/turtles` использует Route Model Binding по username. Старые ссылки с числовыми ID больше не используются; связи между таблицами по-прежнему основаны на `users.id` и `turtles.user_id`.

Проверка: `php artisan test`, затем откройте список пользователей, перейдите в личный и чужой каталоги и проверьте URL.

## Лабораторная №5: комментарии и реляционные связи (этап 1)

Миграция создаёт таблицу `comments` с обязательными внешними ключами `turtle_id` и `user_id`, текстом и служебными датами. После обновления ветки выполните `php artisan migrate`.

Связи Eloquent: `Turtle::comments()`, `User::comments()` — hasMany; `Comment::turtle()`, `Comment::user()` — belongsTo. При окончательном удалении черепахи или удалении автора комментарии удаляются каскадно; мягкое удаление черепахи сохраняет комментарии, поэтому после восстановления они остаются доступны. Отношение к черепахе включает мягко удалённую модель для служебных операций; пользовательский доступ к ней должен проверяться на уровне маршрута/контроллера.

Проверка: `php artisan test --filter=CommentRelationsTest`. Формы, маршруты и обработка пользовательских комментариев реализованы на этапе 2.


## Лабораторная №5: добавление и просмотр комментариев (этап 2)

- На странице `/turtles/{id}` выводятся комментарии в порядке создания, имя и username автора, дата и текст.
- Гости могут читать комментарии активных записей. Авторизованные пользователи могут оставлять комментарии к своим и чужим активным объектам, независимо от владельца.
- `POST /turtles/{turtle}/comments` защищён middleware auth и Gate `comments.create` в CommentRequest. Текст обязателен, не более 2000 символов; Blade экранирует HTML.
- Автор определяется по текущей сессии, черепаха — через Route Model Binding. Переданные вручную user_id и turtle_id игнорируются.
- Для мягко удалённых записей комментарии остаются доступными администратору только для чтения; добавление новых запрещено.
- Проверка: `php artisan test --filter=CommentTest` и затем `php artisan test`.

## Лабораторная №5: дружба пользователей (этап 3)

Миграция создаёт промежуточную таблицу `friendships` с двумя обязательными внешними ключами к `users.id`, уникальной парой `(user_id, friend_id)` и датами. При удалении пользователя входящие и исходящие связи удаляются каскадно.

- `User::friends()` и `User::followers()` — самоссылочные отношения belongsToMany в прямом и обратном направлениях.
- `GET /friends` — список друзей текущего пользователя.
- `POST /users/{username}/friendship` — добавление через syncWithoutDetaching (сохраняет существующих друзей); `DELETE /users/{username}/friendship` — удаление через detach.
- Маршруты защищены middleware auth, Gate friends.manage запрещает добавлять самого себя. Источник связи — текущая сессия, цель — параметр маршрута.
- На данном этапе связи направленные. Автоматическая взаимная дружба добавляется отдельно на расширенном этапе с событиями.
- После обновления выполните `php artisan migrate`, затем `php artisan test --filter=FriendshipTest` и проверьте кнопки на странице пользователей.

## Лабораторная №5: лента друзей (этап 4)

- `GET /feed` — личная лента авторизованного пользователя. Ссылка «Лента друзей» находится в шапке.
- FeedController получает ID друзей через Eloquent belongsToMany и использует SQL-подзапрос в whereIn. Свои записи, записи посторонних пользователей и мягко удалённые объекты не отображаются, в том числе в ленте администратора.
- Сортировка по `created_at DESC, id DESC` (новые записи первыми). Дата catalogued_at не влияет на порядок.
- Используется общий Blade-шаблон каталога: карточки содержат владельца и дату создания. При добавлении друга появляются все его активные записи, при удалении друга они исчезают из ленты.
- Новых миграций нет. Проверка: `php artisan test --filter=FriendFeedTest`.

## Лабораторная №5: подсветка комментариев друзей (этап 5)

На странице любой доступной черепахи комментарии друзей текущего пользователя выделяются зелёным фоном, рамкой, иконкой и надписью «Друг». Собственные комментарии, комментарии остальных пользователей и все комментарии при просмотре гостем не выделяются.

TurtleController загружает ID друзей одним запросом через belongsToMany; Blade проверяет принадлежность автора к этому списку. Подсветка зависит от текущего зрителя и обновляется при следующем открытии страницы после изменения списка друзей. Порядок комментариев остаётся прежним. Используются уже существующие Bootstrap и Font Awesome, новых зависимостей и миграций нет.

Проверка: `php artisan test --filter=FriendCommentTest`.
